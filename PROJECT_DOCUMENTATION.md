# 🌿 АгроЕнциклопедія: Глобальна Документація та База Знань

Цей документ є **повним, вичерпним зліпком усього контексту проєкту**. Він створений для того, щоб ШІ міг миттєво зрозуміти всі архітектурні рішення, правила дизайну та вимоги до контенту без необхідності перечитувати історії чатів. 

**АБСОЛЮТНИЙ ЕТАЛОН ПРОЄКТУ:** Культура **"Груша"** (`content/cultures/hrusha`). Усі нові культури повинні створюватися, повністю спираючись на структуру, глибину та дизайн цього розділу.

---

## 1. 🎯 Глобальна Візія та Контент
Наша мета — створити преміальний, інтерактивний довідник садівника.
- **Глибина:** Енциклопедична точність, написана доступною, простою мовою (як наставник говорить з учнем). Максимальна деталізація процесів, дат, дозувань.
- **Структура культур:** Життєвий цикл розбивається на окремі `.md` файли (10-20 файлів). Типові розділи: Фізіологія, Підщепи, Сорти, Посадка, Полив, Обрізка, Щеплення, Хвороби, Шкідники, Календар захисту, Зима, Збір.
- **Стиль написання:** Без сухої академічної води. Лише перевірена практика.

---

## 2. 🛠 Технологічний Стек та Архітектура
- **Фреймворк**: Next.js (App Router).
- **Контент**: MDX (Markdown + React компоненти).
- **Стилізація**: Vanilla CSS + CSS Змінні (`globals.css`).
- **Шрифти**: 
  - `var(--font-serif)` (Cormorant Garamond) — для преміальних заголовків.
  - `var(--font-body)` (Lora) — для основного тексту.
  - `var(--font-mono)` (JetBrains Mono) — для технічних деталей.
- **Дизайн-система (Glassmorphism)**: Напівпрозорі фони (`var(--color-surface)`), розмиття, м'які тіні (`box-shadow: 0 15px 40px -10px rgba(0,0,0,0.08)`).

---

## 3. 🧩 Еталонні MDX-Компоненти (Суворі Правила)
Звичайні markdown-таблиці та стандартні цитати `> ` **ЗАБОРОНЕНІ** для важливих правил чи кроків.

### 3.1. Структура сторінки
- Початок: `<HeroCover imageSrc="/photos/.../hero.png" chapter="РОЗДІЛ X" title="НАЗВА" subtitle="..." />`
- Зміст: `<TableOfContents />` (автоматично збирає `##` та `###`).
- Кінець (крім останнього розділу): `<NextChapter href="..." title="..." chapterNum="..." />`
- Останній розділ завершується **Епілогом**: `<InfoBlock type="gold" icon="🍐" title="ВІД САДЖАНЦЯ ДО ЩЕДРОГО ВРОЖАЮ">...надихаючий текст курсивом...</InfoBlock>`.

### 3.2. Інформаційні блоки
- **Callout**: `<Callout type="tip" title="Порада">Текст курсивом</Callout>`.
- **InfoBlock**: `<InfoBlock type="gold" icon="📌" title="СХЕМА Х: НАЗВА">Списки або текст</InfoBlock>`.

### 3.3. Таблиці та Процеси (Проблема JSON-рядків)
**КРИТИЧНО ВАЖЛИВО:** Дані в ці компоненти передаються як JSON-рядок (одинарні лапки ззовні, подвійні всередині). 
**ПРАВИЛО АПОСТРОФА:** Всередині JSON-рядка заборонено використовувати звичайний прямий апостроф `'` (наприклад, "м'якоть"), бо це ламає MDX. Завжди використовуйте **типографський апостроф `’` (U+2019)** ("м’якоть").
- **ComparisonTable**: `<ComparisonTable title="СХЕМА X: НАЗВА" headersJSON='["Кол1"]' rowsJSON='[["Значення"]]' />`
- **PremiumProcess**: `<PremiumProcess title="СХЕМА X: НАЗВА" direction="vertical" stepsJSON='[{"title":"Крок 1","desc":"Опис","icon":"🌱"}]' />`

### 3.4. Вкладки та Інтерактив (Календарі)
- **FilterTabs**: `<FilterTabs><FilterTab label="Весна"> #### 🌸 ФЕНОФАЗА ... </FilterTab></FilterTabs>`
- **Діаграми**: `<BranchAngleDiagram schemaBadge="СХЕМА X" />`. 

---

## 4. 🔢 Наскрізна Нумерація Схем
Для кожної культури всі `InfoBlock`, `ComparisonTable`, `PremiumProcess` та інтерактивні діаграми повинні мати наскрізну нумерацію: "СХЕМА 1:", "СХЕМА 2:", аж до кінця останнього розділу (зазвичай ~60-70 схем).

2. **Візуальний аналіз (MUST DO):** Ніколи не вгадуй вміст зображення за назвою файлу. ШІ ПОВИНЕН використати `view_file`, щоб фізично розпізнати, що зображено, і прийняти рішення про його доречність у тексті.
