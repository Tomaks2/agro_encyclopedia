# 📝 СТИЛЬ КОНТЕНТУ ТА MDX-КОМПОНЕНТИ (CONTENT STYLE GUIDE)

Цей проект використовує спеціальний парсер (MDX), який перетворює звичайний Markdown у преміальні інтерактивні React-компоненти. Наша мета — створити **"Золотий стандарт"** (еталонний дизайн). 
**Еталон оформлення:** Дивись папку `content/cultures/hrusha`. Усі нові культури повинні виглядати так само досконало.

---

## 1. Структура сторінки та Навігація

Кожна сторінка `.md` ПОВИННА починатися з `HeroCover` та `TableOfContents`, і закінчуватися `NextChapter`.

```tsx
<HeroCover 
  imageSrc="/photos/назва_культури/hero/назва_розділу.png" 
  chapter="РОЗДІЛ X" 
  title="НАЗВА РОЗДІЛУ" 
  subtitle="Короткий надихаючий підзаголовок" 
/>

<TableOfContents />

... контент розділу ...

<NextChapter href="/uk/назва_культури/наступний-розділ" title="НАЗВА НАСТУПНОГО РОЗДІЛУ" chapterNum="Розділ Y" />
```

- **Заголовки:** Використовуйте тільки `##` (H2) та `###` (H3). Вони автоматично збираються у зміст.
- **Епілог:** Останній розділ культури ПОВИНЕН завершуватися блоком Епілогу замість `NextChapter`:
```html
## Епілог: Назва
<InfoBlock type="gold" icon="🍐" title="ВІД САДЖАНЦЯ ДО ЩЕДРОГО ВРОЖАЮ">
  *Надихаючий текст курсивом...*
  **Побажання щедрих врожаїв!**
</InfoBlock>
```

## 2. Інформаційні блоки (Заборони звичайних списків та цитат)
Звичайні списки правил або стандартні цитати `> ` **СУВОРО ЗАБОРОНЕНІ** для важливого контенту.

### Callout (Основний інформаційний блок)
Використовуйте для важливих рекомендацій, порад, попереджень.
```tsx
<Callout type="tip" title="Практична порада">
  Цей текст буде автоматично виділено курсивом. 
</Callout>
```
Доступні типи: `tip` (зелений), `warning` (помаранчевий), `info` (синій), `danger` (червоний).

### InfoBlock (Алгоритми, Правила, Санітарія)
Використовуйте для виділення важливих правил (наприклад, "Схема посадки", "Правила поливу").
```tsx
<InfoBlock type="gold" icon="📌" title="СХЕМА 1: ЗОЛОТЕ ПРАВИЛО">
  - **Пункт 1:** Опис
  - **Пункт 2:** Опис
</InfoBlock>
```
Доступні типи: `gold`, `green`, `blue`, `red`. Обов'язково додавайте `title` у форматі "СХЕМА Х: НАЗВА".

## 3. Таблиці та Процеси (Наскрізна нумерація "СХЕМА X")
Кожна культура повинна мати наскрізну нумерацію схем від 1 до ~60-70.

### ComparisonTable (Для всіх характеристик та порівнянь)
**КРИТИЧНО ВАЖЛИВО:** Дані передаються як JSON-рядки (`headersJSON` та `rowsJSON`). Одинарні лапки ззовні, подвійні всередині.
**УВАГА:** Якщо всередині JSON-рядка вам потрібен апостроф (наприклад, у слові м'якоть), використовуйте **ВИКЛЮЧНО типографський апостроф `’` (U+2019)**. Звичайний прямий апостроф `'` зламає компіляцію MDX!
```tsx
<ComparisonTable
  title="СХЕМА 10: СОРТИ ДЛЯ УКРАЇНИ"
  headersJSON='["Параметр", "Значення"]'
  rowsJSON='[
    ["Термін збору", "Серпень"],
    ["Опис", "М’якоть дуже солодка"] 
  ]'
/>
```

### PremiumProcess (Тільки для покрокових інструкцій)
Використовується для інструкцій (Крок 1, Крок 2), наприклад посадка, дозарювання.
```tsx
<PremiumProcess
  title="СХЕМА 11: ПРОЦЕС ПОСАДКИ"
  direction="vertical"
  stepsJSON='[{"title": "Крок 1", "desc": "Викопати яму", "icon": "⛏️"}, {"title": "Крок 2", "desc": "Полити", "icon": "💧"}]'
/>
```

## 4. Складні структури (Календарі та Системи)

### FilterTabs (Для календарів захисту або догляду)
Коли інформації багато (наприклад, хвороби по фазах розвитку), розбивайте її на вкладки. Заголовки всередині вкладок оформлюйте як `####`.
```tsx
<FilterTabs>
  <FilterTab label="Весна">
    #### 🌸 ФЕНОФАЗА: РОЗПУСКАННЯ БРУНЬОК
    Текст та таблиці...
  </FilterTab>
  <FilterTab label="Осінь">
    #### 🍂 ФЕНОФАЗА: ОПАДАННЯ ЛИСТЯ
    Текст та таблиці...
  </FilterTab>
</FilterTabs>
```

### Інтерактивні Тренажери
Якщо вмикаєте специфічні React-компоненти (наприклад `<BranchAngleDiagram />`), передавайте пропс `schemaBadge` для збереження загальної нумерації:
```tsx
<BranchAngleDiagram schemaBadge="СХЕМА 12" />
```

## 5. Дизайн-Система (Glassmorphism)
- **Glassmorphism:** Картки, інформаційні панелі мають напівпрозорий фон, розмиття та плавні тіні. Це преміальний "кіфолк" дизайн.
- **Шрифти:** Ніколи не вбудовуйте стилі прямо в Markdown. Дизайн вже закладено в компонентах.
- Уникайте сухих академічних текстів. Робіть контент візуально багатим, використовуючи емодзі-іконки в `InfoBlock` та `PremiumProcess`.
