## 1. Головна мета проєкту

Мета каталогу насінництва й селекції:

- пояснити, як збирати, очищати, ферментувати, сушити, тестувати та зберігати власне насіння;

- дати культура-специфічні протоколи для томата, гарбузових, кукурудзи, пасльонових, бобових, капустяних, коренеплодів, зеленних, багаторічних культур, плодових дерев, кісточкових, винограду й ягід;

- вести облік ліній, партій насіння, контрольних дослідів, ризиків і фітосанітарної відповідальності.

## 2. Обов’язкові редакційні правила

### Достовірність

1. Не вигадувати факти, цифри, строки, дозування, відстані ізоляції, юридичні висновки або результати експериментів.
2. Кожне конкретне твердження, числове значення або визначення має мати надійне джерело або бути чітко позначене як практичне спостереження/гіпотеза.
3. Розділяти:
   - підтверджений факт;
   - рекомендацію джерела;
   - думку або практичну пораду автора;
   - неофіційне спостереження;
   - невизначеність і розбіжність між джерелами.
4. Не подавати спостереження садівників як науково встановлений факт.
5. Для неофіційних спостережень обов’язково вказувати, що це не заміна контрольованого досліду.
6. Не приховувати розбіжності між джерелами.
7. Перевагу надавати університетським extension-матеріалам, офіційним українським установам, FAO, UPOV, науковим публікаціям і профільним методичним посібникам.
8. Для законодавства України перевіряти чинну редакцію на офіційних ресурсах.

### Повнота

- Не обмежувати глибину штучним лімітом.
- Розкривати причину процедури, не лише саму процедуру.
- Для кожного протоколу пояснювати: навіщо це робиться, коли це доречно, що може піти не так, як перевірити результат і коли метод не застосовувати.
- Для селекції не обіцяти, що домашній добір автоматично створить «елітний сорт». Пояснювати багаторічність, генетичну мінливість, обсяг популяції, повторність і перевірку стабільності.
- Для F1 пояснювати, що отримання гібридного насіння можливе технічно, але потребує батьківських форм, контрольованого схрещування, повторюваності та перевірки; не називати домашню одноразову схему готовим комерційним гібридом.

### Стиль

Орієнтир — еталонні глави 01–02:

```text
HeroCover → TableOfContents → Callout → підрозділи → InfoBlock/таблиці → головний підсумок → Джерела → NextChapter
```

Текст має бути українською, професійним, але зрозумілим. Потрібні короткі абзаци, логічні підрозділи, практичні списки, порівняльні таблиці та явні застереження.

### Технічні заборони

- Не використовувати `<PremiumProcess>`.
- Не використовувати `<ComparisonTable>`.
- Для таблиць використовувати стандартний GFM Markdown:

```md
| Поняття | Практичне значення |
| :--- | :--- |
| ... | ... |
```

- Не залишати в публічному тексті внутрішні редакторські нотатки: `CAVEAT`, `Тест 5+ тверджень`, `U не включено`, `find`, внутрішні назви компонентів або технічні звіти.
- `REPORT_*` і `SOURCES_*` — внутрішні робочі матеріали, не публічний контент.
- Не створювати нові зображення або не підключати assets без перевірки їхнього фактичного змісту.
- Усі написи на майбутніх зображеннях мають бути лише українською.

### Найближчі блоки

1. Візуально перевірити глави 01–03 та весь sidebar після додавання перших двох глав.
2. Перевірити всі переходи між 27 seed-розділами.

   - або залишити її у власному каталозі кукурудзи з явним related-link;
   - або створити прозорий proxy/registry entry у seed-каталозі.
4. Перевірити й прибрати публічні редакторські артефакти.
5. Перевірити HeroCover assets; не залишати повторну томатну картинку там, де вона не відповідає культурі.

### Високий пріоритет перед деплоєм

1. Виправити clean install: `npm ci` зараз треба перевірити в чистому середовищі після узгодження lock-файла.
2. Перевірити `npm audit --omit=dev` і сумісні оновлення production-залежностей.
3. Довести `npm run lint` до нуля або скласти обґрунтований список винятків.
4. Провести повний route smoke-test для всіх metadata-каталогів.
5. Уніфікувати legacy MDX винограду.
6. Замінити або свідомо оформити відсутні зображення за manifest-ом.
7. Повторити desktop/mobile screenshot-аудит.
8. Тільки після цього готувати release candidate і деплой.

### Контентні наступні етапи

- Після технічної стабілізації — розширювати культура-специфічні протоколи.
- Для томата окремо поглибити відбір материнських рослин, мокре вилучення, ферментацію, сушіння, тест схожості, зберігання, контрольоване схрещування та роботу з F1/F2.
- Аналогічно поглибити огірок, кавун, гарбузові, кукурудзу та інші культури.
- Для дерев розгорнути окремі матеріали про сіянці, клонові/насіннєві підщепи, щеплення, живцювання, стратифікацію, розсадництво та перевірку сорту.
- Для кожної культури зберігати джерельний реєстр і не змішувати підтверджені дані з практичними спостереженнями.

## 9. Поточні обмеження та застереження

- Ця робоча копія не має `.git`-історії; архів — snapshot поточного стану, а не Git commit.
- У репозиторії відсутні передбачені в еталоні assets обкладинок глав 01–02; `HeroCover` не ламає сторінку, але візуально використовується fallback.
- Англійська локаль навмисно не публікується на цьому етапі.
- Локальний успішний build не доводить готовність до production, доки не вирішені clean install, lint, audit, legacy MDX і media manifest.
- Не вважати архів дозволом на деплой або публікацію.

## 10. Критерій завершення наступного етапу

Наступний редактор може вважати поточний handoff прийнятим, якщо він:

- бачить глави 01–02 у seed-каталозі;
- бачить нумерацію `01–02–03`;
- відкриває категорію насінництва з головної сторінки;
- проходить `npx tsc --noEmit` і `npm run build`;
- не вносить контентних тверджень без джерел;
- залишає окремий звіт про свої зміни та наступні ризики.
